# Darka

Сайт нейросети Darka: лендинг, регистрация и вход, чат с четырьмя моделями и админка.
Стек: Next.js 14, Neon (Postgres), без внешних сервисов авторизации.

## Запуск на Vercel

1. Распакуйте архив и загрузите папку в репозиторий на GitHub.
2. В Vercel нажмите **Add New → Project** и выберите этот репозиторий.
3. До первого деплоя откройте **Settings → Environment Variables** и добавьте переменные из таблицы ниже.
4. Нажмите **Deploy**.

Таблицы в базе создаются сами при первом обращении. Ничего запускать вручную не нужно.

## Переменные окружения

| Переменная  | Что это |
|-------------|---------|
| `DATABASE`  | Строка подключения к Neon (`postgresql://...?sslmode=require`) |

Адрес моделей больше не задаётся переменными окружения. Один адрес для всех четырёх моделей администратор вводит
в **админке** (верхний блок «Адрес моделей»). Адрес сохраняется в базе, перезапускать ничего не нужно.

Необязательные:

| Переменная      | Что это |
|-----------------|---------|
| `MODEL_API_KEY` | Если задана, уходит в заголовке `Authorization: Bearer ...` ко всем четырём моделям |
| `AUTH_SECRET`   | Секрет для подписи сессий. Если не задан, вычисляется из `DATABASE` |

После изменения переменных нужно сделать **Redeploy**.

## Как сайт обращается к моделям

На адрес моделей (задаётся в админке) уходит `POST` с JSON. Нужная модель указывается полем `model`:

```json
{
  "model": "shadow",
  "messages": [
    { "role": "user", "content": "Привет" },
    { "role": "assistant", "content": "Здравствуйте!" },
    { "role": "user", "content": "Что ты умеешь?" }
  ],
  "stream": false
}
```

В `messages` попадают последние 20 сообщений разговора. Роли всегда чередуются и разговор начинается с `user`:
два сообщения одной роли подряд (так бывает после неудачного запроса) склеиваются в одно. Если у пользователя
задан главный промпт или включён режим «Рассуждение», первым идёт сообщение с ролью `system`.

Ответ можно вернуть в любом из форматов:

- как у OpenAI: `{"choices":[{"message":{"content":"..."}}]}`
- с полем `response`, `reply`, `answer`, `text`, `output`, `result`, `message` или `content`
- обычным текстом

Если ваши модели ждут другой формат запроса, измените функцию `callModel` в `lib/backends.js`.
Таймаут ответа — 55 секунд.

## Если чат пишет, что модели недоступны

Откройте админку и нажмите **«Проверить»** рядом с адресом моделей. Сайт отправит тестовый вопрос так же,
как чат, и покажет ответ сервера или точную причину ошибки. Администратор видит причину и в самом чате:
второй строкой под текстом ошибки. Обычные пользователи видят только короткое сообщение.

| Сообщение в чате | Что случилось |
|------------------|---------------|
| Модели временно недоступны | Адрес моделей не сохранён в админке |
| Не удалось связаться с моделью | Адрес не открывается. Ссылка trycloudflare перестаёт работать, когда закрыт туннель |
| Модель сейчас не отвечает | Сервер ответил ошибкой: 530 — туннель закрыт, 502 — не запущен uvicorn, 404/405 — неверный путь, 500 — ошибка в коде на Colab (traceback в выводе ячейки) |
| Модель отвечает слишком долго | Генерация идёт дольше 55 секунд. Уменьшите `max_new_tokens` или задайте `max_time` |
| Модель вернула пустой ответ | Сервер ответил, но без текста |

### Сервер в Google Colab

Готовая ячейка лежит в [`colab/darka_server.py`](colab/darka_server.py). Запускайте её после ячейки, где загружены
`tok` и `model`. Что она делает:

- передаёт модели системный промпт сайта: главный промпт из «Кастомизации» и режим «Рассуждение»;
- склеивает реплики одной роли подряд, иначе строгие шаблоны (Mistral, Gemma, Llama 2) падают с ошибкой
  `Conversation roles must alternate`;
- ограничивает генерацию 45 секундами (`max_time`), чтобы ответ приходил раньше таймаута сайта;
- генерирует ответы по одному, остальные запросы ждут очереди;
- читает лог cloudflared: если его не читать, буфер переполняется и туннель зависает;
- при повторном запуске перезапускает сервер, а туннель не трогает, поэтому адрес остаётся прежним;
- по адресу туннеля в браузере показывает `{"status": "ok"}`, так легко проверить, что всё работает.

Адрес trycloudflare меняется после каждого перезапуска среды Colab. Новый адрес нужно вставить в админку
и нажать «Сохранить».

## Админка

1. После деплоя **первым делом** зарегистрируйтесь с именем **MrDarko** (регистр не важен).
   Этот аккаунт автоматически становится администратором. Пока имя не занято, его может занять кто угодно.
2. Откройте `/admin` (кнопка «Админка» есть в боковой панели чата).
3. Там можно искать пользователей, банить и разбанивать (с причиной), выдавать Pro на 7, 30, 90, 365 дней или бессрочно, снимать подписку. Повторная выдача продлевает действующую подписку.

Администратора заблокировать нельзя. Забаненный пользователь не может войти, а уже открытые сессии перестают работать при следующем запросе.

## Доступ к моделям

| Модель | Доступ |
|--------|--------|
| Darka 0.1, Darka Shadow 1.0 | все с аккаунтом |
| Darka Quiziw 7.0, Darka 0.2 Enchanted | подписка Pro и администратор |

Менять доступ можно в `lib/models.js` (поле `plan`).
Без входа в аккаунт спросить Darka нельзя: `/chat` ведёт на страницу входа, а API чата отвечает 401.
